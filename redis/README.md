# Redis 工程实验路线

## 目标
以 Java 后端工程岗位为目标，通过可复现实验建立原理理解、设计、排障和优化能力。完成实验不等同于生产经验，不以背诵或实验数量直接认定精通。

## 技术基线
固定 Redis 版本；集群与单机语义分别验证。遵循仓库 Maven 结构，具体版本在实现阶段固定。

## 能力清单

| 模块 | 核心知识 | 验证实验 |
|---|---|---|
| 数据结构 | String、Hash、List、Set、ZSet、Bitmap、Stream | Lab 01：业务数据结构选型 |
| 缓存一致性 | Cache Aside、TTL、失效、并发竞争 | Lab 02：数据库与缓存一致性 |
| 缓存异常 | 穿透、击穿、雪崩、热点键 | Lab 03：热点商品缓存保护 |
| 原子性与分布式协调 | Lua、事务、WATCH、锁租约 | Lab 04：秒杀库存与锁租约失效 |
| 持久化与恢复 | RDB、AOF、fsync、重写 | Lab 05：Redis 崩溃后的数据恢复 |
| 复制与 Sentinel | 复制、故障转移、脑裂风险 | Lab 06：主节点宕机与哨兵切换 |
| Cluster 与扩容 | 哈希槽、MOVED/ASK、迁移、多键限制 | Lab 07：集群扩容与槽迁移 |
| 性能与运维 | big key、hot key、淘汰、慢日志、内存 | Lab 08：缓存服务性能故障排查 |

## 实验 Backlog

| 状态 | 编号 | 实验 | 执行与验收 |
|---|---|---|---|
| 待做 | 01 | 业务数据结构选型 | 实现计数、排行、去重、队列等场景，比较内存与操作复杂度；验证业务结果及 TTL，记录不同结构内存与延迟 |
| 待做 | 02 | 数据库与缓存一致性 | 实现缓存读写并注入更新/删除失败及并发读写；复现陈旧值，验证修复策略与最终一致性窗口 |
| 待做 | 03 | 热点商品缓存保护 | 构造不存在键、热点过期和批量过期，应用负缓存、互斥重建、抖动 TTL；对比数据库请求量、延迟及错误率，说明负缓存边界 |
| 待做 | 04 | 秒杀库存与锁租约失效 | 实现 Lua 原子扣减并复用 distributed-lock 模块的锁案例，验证租约过期与 fencing 思路；并发库存不超卖，复现旧持有者风险，区分原子脚本与跨系统事务 |
| 待做 | 05 | Redis 崩溃后的数据恢复 | 比较不同持久化策略下进程终止与恢复，记录写入负载；核对已写数据及丢失窗口、恢复耗时和资源开销 |
| 待做 | 06 | 主节点宕机与哨兵切换 | 搭建主从和 Sentinel，注入主节点故障及网络隔离；记录选主、客户端重连、数据差异与异步复制风险 |
| 待做 | 07 | 集群扩容与槽迁移 | 搭建多节点集群，执行槽迁移及节点故障，验证客户端路由；记录槽分布、重定向、迁移影响及跨槽失败场景 |
| 待做 | 08 | 缓存服务性能故障排查 | 构造大键、热键与内存压力，使用 INFO、SLOWLOG、压测诊断；报告延迟、命中率、淘汰和内存曲线，验证修复及安全删除策略 |

## 交付规范
每个实验包含问题背景、假设、架构或时序图、可运行代码、固定版本环境、自动化测试或故障脚本、实际日志、对照结果、局限与清理命令。压测和故障注入仅在隔离环境进行。按 `redis/lab-XX-*/` 组织，完成后更新状态及成果链接；一个实验一个 PR。
