# Spring Cloud 工程实验路线

## 目标
以 Java 后端工程岗位为目标，通过可复现实验建立原理理解、设计、排障和优化能力。完成实验不等同于生产经验，不以背诵或实验数量直接认定精通。

## 技术基线
按 Spring Boot 与 Spring Cloud 官方兼容矩阵固定 BOM；Alibaba 组件单独标注。遵循仓库 Maven 结构，具体版本在实现阶段固定。

## 能力清单

| 模块 | 核心知识 | 验证实验 |
|---|---|---|
| 服务架构与调用 | 服务拆分、HTTP、OpenFeign、契约 | Lab 01：订单与库存微服务调用 |
| 注册发现与负载均衡 | DiscoveryClient、LoadBalancer、Nacos/Eureka | Lab 02：多实例服务发现与下线 |
| 网关与安全 | Gateway、路由、过滤器、认证授权 | Lab 03：统一 API 网关 |
| 配置管理 | Config 或 Nacos、环境隔离、动态刷新 | Lab 04：多环境配置与回滚 |
| 服务韧性 | CircuitBreaker、Resilience4j、限流、隔离 | Lab 05：下游雪崩与熔断恢复 |
| 分布式一致性 | Saga、Outbox、补偿、幂等 | Lab 06：订单库存支付最终一致性 |
| 可观测性 | Micrometer、Tracing、OpenTelemetry、日志关联 | Lab 07：跨服务慢请求追踪 |
| 部署与治理 | 容器、健康检查、灰度、回滚 | Lab 08：微服务滚动升级与故障演练 |

## 实验 Backlog

| 状态 | 编号 | 实验 | 执行与验收 |
|---|---|---|---|
| 待做 | 01 | 订单与库存微服务调用 | 搭建两服务及契约测试，配置连接、读取超时与错误映射；验证正常、超时、错误响应，记录调用链及接口契约 |
| 待做 | 02 | 多实例服务发现与下线 | 选定一种注册中心，部署多实例并注入下线、重启；验证实例发现、分配及故障窗口，记录健康检查配置 |
| 待做 | 03 | 统一 API 网关 | 实现路由、请求 ID、令牌校验和下游访问限制；验证未授权、过期令牌、路由及请求追踪，不暴露密钥 |
| 待做 | 04 | 多环境配置与回滚 | 建立 dev/test 配置，演练变更、刷新及回滚；验证配置来源、刷新范围与失败回退，敏感值不入库 |
| 待做 | 05 | 下游雪崩与熔断恢复 | 注入延迟和错误，对照超时、熔断、隔离和有限重试；验证熔断状态转换、恢复及重试放大风险，记录延迟和错误率 |
| 待做 | 06 | 订单库存支付最终一致性 | 实现模拟订单 Saga 或 Outbox，注入中间失败和重复事件；验证成功、补偿、重放及状态不变量，说明不保证全局 ACID |
| 待做 | 07 | 跨服务慢请求追踪 | 接入指标、日志与追踪，注入慢调用并定位瓶颈；通过 trace ID 关联服务日志，提供指标与链路证据 |
| 待做 | 08 | 微服务滚动升级与故障演练 | 固定镜像与配置，部署多个实例，模拟升级失败和回滚；验证就绪检查、版本兼容、请求错误率及回滚过程 |

## 交付规范
每个实验包含问题背景、假设、架构或时序图、可运行代码、固定版本环境、自动化测试或故障脚本、实际日志、对照结果、局限与清理命令。压测和故障注入仅在隔离环境进行。按 `spring-cloud/lab-XX-*/` 组织，完成后更新状态及成果链接；一个实验一个 PR。

## 简历表达
完成相应实验后据实描述：熟练掌握 Spring Cloud 的核心机制，能够复现和分析典型工程问题，设计解决方案并通过测试或压测验证。没有真实生产经验时不声称生产调优或故障处理经历。
